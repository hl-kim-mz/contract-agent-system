> MEGATHON 2026 해커톤 | Track 3: Multi-Agent System
> **v1.0** — 기술 구현 세부사항 제외, 비즈니스·제품 관점

---

## 1. 제품 개요

**서비스명**: Contract Agent System (CAS)

메가존클라우드(MZC) 영업팀이 고객사와 체결하는 다양한 계약서(NDA, MSA, SI 도급, SLA, 유지보수 등)를 업로드하면, AI가 **조항 분석 → 리스크 탐지 → 변경 이력 추적 → 내부 검토 라우팅 → 히스토리 검색**을 자동 처리하는 계약 검토 지원 시스템이다.

**설계 철학**: "AI가 필요한 곳에만 AI를 쓴다." — 규칙으로 해결 가능한 영역은 규칙으로, AI는 비정형 텍스트 이해·리스크 판단·자연어 검색 등 판단이 필요한 영역에만 투입한다.

---

## 2. 문제 정의

### 배경

메가존클라우드는 영업팀이 SFDC(Salesforce)에서 영업기회를 생성하고, DMS(Deal Management System)를 통해 계약 라이프사이클을 관리한다. 계약은 **사업성 검토 → 계약검토 → 계약관리(정산) → 마감** 4단계를 거치며, QIS(구매품의), A10(내부결재), ASP/ACP/MCIS(정산) 등 복수의 시스템과 연동된다.

### Pain Points

| 문제 | 현재 방식 | 영향 |
|------|-----------|------|
| 계약서 형태가 프로젝트/고객사마다 상이 | 영업팀 담당자가 수동 검토 | 검토 품질 편차, 리스크 누락 |
| 법무 리스크 조항 식별 | 계약팀·법무팀 의존 (병목) | 계약 체결까지 평균 수일 소요 |
| 비표준계약 판단 기준 불명확 | 계약팀 판단에 의존 | 기준 편차, 에스컬레이션 지연 |
| 버전 변경 이력 관리 | 파일명 수기 버전관리 (v1, v2_최종, v2_최최종…) | 변경점 파악 불가 |
| 부서 간 검토 공유 | 이메일/Slack 메신저 분산 | 진행 현황 추적 불가 |
| 과거 계약 이력 검색 불가 | 파일 탐색기 수동 검색 | 유사 계약 참조 불가, 동일 실수 반복 |
| QIS 구매품의 연동 판단 | 담당자가 수동으로 QIS 요청 생성 | 누락·지연 빈번 |
| 전자서명 / 최종 승인 | 오프라인 또는 DocuSign 별도 툴 | 프로세스 단절, 상태 추적 불가 |

### 핵심 가설

> "계약서를 업로드하면 AI가 5분 안에 리스크 리포트를 생성하고, MZC 내부 기준(계약팀 → 법무팀 → 본부장)에 맞게 자동 라우팅하면 계약 체결 사이클을 **수일 → 당일**로 단축할 수 있다."

## 3. 타겟 사용자

| 페르소나 | 역할 | CAS 활용 맥락 |
|----------|------|---------------|
| **영업팀 담당자** | 고객사 계약서를 최초 수령·업로드하는 주체 | 계약서 업로드, 리스크 리포트 확인, 과거 계약 검색 |
| **계약팀 (CM)** | 계약 검토·승인 1차 게이트키퍼 | 리스크 리포트 기반 검토, 승인/반려/의견 입력 |
| **법무팀** | HIGH 리스크 계약의 법적 검토 담당 | 고위험 조항 상세 검토, 수정 의견 제시 |
| **본부장 / 담당 임원** | 최종 승인권자 | 리스크 요약 확인 후 최종 승인/반려 |
| **재무팀** | 대형 계약(10억+) 재무 리스크 병렬 검토 | 재무 조건 검토 |

## 4. 제품이 지원하는 업무 흐름

CAS는 MZC의 실제 계약 프로세스 중 **"계약서 작성 ~ 검토/승인"** 구간과 **히스토리 검색**을 지원한다.

```
MZC 계약 프로세스                     CAS 지원 영역
─────────────────                   ──────────────
SFDC 영업기회 생성
       ↓
사업성 검토
       ↓
계약서 작성 (영업팀)         ←——  DOCX 업로드 → AI 리스크 분석
       ↓
계약검토 요청 (CM검토중)     ←——  자동 라우팅 (계약팀/법무팀/본부장)
       ↓
검토/승인 (계약팀)           ←——  워크플로우 승인/반려/의견
       ↓
날인
       ↓
구매품의 연동               ←——  계약 히스토리 검색
       ↓
정산 연동
```

## 5. 제품 범위 (MVP)

### In Scope

| 기능 | 사용자 가치 |
|------|------------|
| DOCX 업로드 및 자동 구조화 | 수동 계약서 검토 시간 제거 |
| AI 기반 리스크 분석 리포트 | 리스크 조항 자동 식별, 검토 품질 균일화 |
| 리스크 판단 프롬프트 커스터마이징 | 계약 유형별 기준 유연 조정 |
| 이전 버전 대비 조항 Diff 뷰 | 버전 간 변경사항 즉시 파악 |
| 계약서 자동 버저닝 | 동일 고객사 기준 이력 자동 관리 |
| 전체 계약 히스토리 자연어 검색 | 과거 유사 계약 즉시 참조 |
| MZC 기준 검토 라우팅 + 승인/반려 | 수동 에스컬레이션 제거, 프로세스 표준화 |
| 계약서 목록 및 상태 대시보드 | 전체 계약 현황 한눈에 파악 |

### Stretch Goal (시간 여유 시)

- 프로젝트별 컨텍스트/제약사항 프롬프트 관리
- 비표준계약 자동 판별 및 에스컬레이션 플래그

### Out of Scope (명시적 제외)

- 실제 DocuSign/전자서명 연동
- 실제 Slack/이메일 알림 발송
- SFDC, A10, QIS, ASP/ACP/MCIS 실연동
- 다국어 지원
- 모바일 반응형

## 6. 핵심 기능 상세

### 6.1 계약서 업로드 및 구조화

영업팀 담당자가 DOCX 형식의 계약서를 업로드하면, 시스템이 자동으로 다음을 추출·구조화한다:

- **계약 유형 분류**: NDA, MSA, SI 도급, SLA, 유지보수, 외주도급 등
- **표준/비표준 판별**: MZC 표준 계약서 여부 자동 식별
- **당사자 정보**: 갑(메가존클라우드), 을(고객사) 식별
- **핵심 날짜**: 계약일, 시작일, 종료일, 갱신 조건
- **금액 정보**: 계약금액, 지급 조건, 지체상금율
- **조항 분리**: 개별 조항 단위로 분리하여 리스크 분석 대상화

### 6.2 AI 리스크 분석

구조화된 계약서 데이터를 기반으로 AI가 MZC 내부 기준에 따라 리스크를 자동 탐지한다.

**분석 결과물:**
- 전체 리스크 등급 (HIGH / MEDIUM / LOW)
- 조항별 리스크 상세 (위험 근거, 수정 제안, 예상 손익 영향)
- 핵심 우려사항 (3개 이내 요약)
- MZC 표준 계약 대비 주요 차이점
- 에스컬레이션 필요 여부 판단

### 6.3 버전 Diff 뷰

동일 고객사의 이전 계약 버전이 존재할 경우, 조항별 변경사항을 자동 비교한다.

- 추가/삭제/수정된 조항 시각화
- 변경된 조항의 리스크 영향도 요약
- 버전 간 리스크 등급 변화 추적

### 6.4 검토 워크플로우

리스크 분석 결과에 따라 MZC 내부 기준으로 검토자를 자동 배정하고, 순차/병렬 승인 프로세스를 관리한다.

- 검토 요청 자동 생성
- 승인/반려/의견 입력 기능
- 다음 단계 자동 진행

### 6.5 히스토리 검색

전체 계약서 아카이브를 자연어로 검색하여 과거 사례를 즉시 참조한다.

- 현재 조회 중인 고객사가 기본 필터로 적용
- 검색 결과에 출처 하이라이트 표시
- 계약서 상세 페이지 우측에 내장

### 6.6 프롬프트 커스터마이징

AI의 리스크 판단 기준을 사용자가 직접 조정할 수 있다.

- 계약 유형별(NDA, MSA, SI 등) 별도 기준 설정
- MZC 내규·표준 계약 기준 반영
- 수정 후 즉시 재분석 가능

## 7. 비즈니스 규칙

### 7.1 리스크 탐지 기준

| 리스크 유형 | MZC 기준 (정상) | 탐지 조건 (위험) | 등급 |
|------------|----------------|-----------------|------|
| 무제한 배상책임 | 계약금액 100% 이내 | 배상한도 미설정 또는 계약금액 초과 | HIGH |
| IP 완전이전 | 공동소유 또는 기존 IP 제외 | 개발 산출물 지재권 전부 이전 | HIGH |
| 일방적 해지권 | 양 당사자 서면 통지 30일 전 | 갑 단독 해지 + 위약금 없음 | HIGH |
| CR 절차 미정의 | 서면 합의 + 비용 정산 기준 | 변경요청 처리 절차 미명시 (SI) | HIGH |
| 과도한 지체상금 | 0.05%/일 이내 | 0.1%/일 초과 | MEDIUM |
| 자동갱신 조건 | 갱신 거절 기한 명시 | 갱신 거절 기한 미명시 | MEDIUM |
| 분쟁 관할 불리 | 서울중앙지방법원 | 상대방 소재지 법원 지정 | MEDIUM |
| 하자보수 기간 미달 | 1년 이상 | 1년 미만 명시 (SI 계약) | MEDIUM |
| 비밀유지 기간 미정 | 계약 종료 후 3년 | 계약 종료 후 기간 명시 없음 | LOW |

### 7.2 검토 라우팅 규칙

| 조건 | 라우팅 대상 | 검토 방식 |
|------|------------|-----------|
| 전체 리스크: HIGH | 계약팀 → 법무팀 → 본부장 | 순차 3단계 |
| 전체 리스크: MEDIUM | 계약팀 → 담당 임원 | 순차 2단계 |
| 전체 리스크: LOW | 영업팀 담당자 자체 승인 | 1단계 |
| 계약금액 10억 이상 | 재무팀 병렬 검토 추가 | 기존 흐름에 +1 (병렬) |
| IP 완전이전 조항 존재 | 기술법무 검토 추가 | 기존 흐름에 +1 (순차) |
| 비표준계약 플래그 | 계약팀 에스컬레이션 필수 | 최우선 |
| CR 절차 미정의 (SI 계약) | 계약팀 + 프로젝트팀장 | 기존 흐름에 +1 (병렬) |

### 7.3 계약 상태 전이

```
DRAFT → PARSING → RISK_REVIEWED → PENDING_APPROVAL → APPROVED / REJECTED
```

| CAS 상태 | 비즈니스 의미 |
|----------|-------------|
| DRAFT | 계약서 업로드 완료, 분석 대기 |
| PARSING | 계약서 구조화 진행 중 |
| RISK_REVIEWED | 리스크 분석 완료, 검토 라우팅 대기 |
| PENDING_APPROVAL | 검토 진행 중 (승인 대기) |
| APPROVED | 계약검토 승인 완료 |
| REJECTED | 계약검토 반려 (수정 요청) |

## 9. 사용자 시나리오

### 시나리오 1: 신규 계약서 리스크 검토

1. 영업팀 김 매니저가 고객사로부터 SI 도급 계약서(DOCX)를 수령한다.
2. CAS에 접속하여 계약서를 업로드하고, 고객사명과 계약 유형(SI 도급)을 선택한다.
3. 시스템이 계약서를 자동 구조화하고, AI가 리스크 분석을 수행한다.
4. 1분 내에 리스크 리포트가 생성된다: HIGH 리스크 3건 (무제한 배상, CR 미정의, 과도한 지체상금).
5. 시스템이 자동으로 계약팀 → 법무팀 → 본부장 순차 검토를 요청한다.
6. 김 매니저는 리포트의 수정 제안을 참고하여 고객사와 협상 포인트를 준비한다.

### 시나리오 2: 버전 비교 및 변경 추적

1. 영업팀 박 대리가 고객사 A와의 NDA v2를 업로드한다.
2. 시스템이 자동으로 v1과의 Diff를 생성한다.
3. 비밀유지 기간이 3년 → 1년으로 단축된 것이 감지된다.
4. AI가 해당 변경의 리스크 영향을 요약하여 보여준다.

### 시나리오 3: 과거 계약 참조 검색

1. 계약팀 이 팀장이 고객사 B의 SI 계약을 검토 중이다.
2. 검색 패널에서 "B사와의 과거 계약에서 CR 조항은 어떻게 처리했나?"를 입력한다.
3. 과거 계약 3건에서 CR 관련 조항과 처리 방식이 검색 결과로 제시된다.
4. 이 팀장은 선례를 참고하여 현재 계약의 CR 조항 수정 방향을 결정한다.

### 시나리오 4: 리스크 기준 커스터마이징

1. 계약팀장이 SI 계약의 지체상금 기준을 0.05%/일 → 0.08%/일로 완화하려 한다.
2. 프롬프트 설정 화면에서 SI 전용 프리셋의 지체상금 기준을 수정한다.
3. 기존 계약서에 대해 즉시 재분석을 실행하여 변경된 기준의 영향을 확인한다.

## 12. 데모 시나리오 (해커톤 발표용)

> MZC 영업팀 담당자가 고객사 SI 도급 계약서를 처음 받은 상황

| 단계 | 행위 | 기대 결과 |
|------|------|-----------|
| 1. Upload | 영업팀 담당자가 SI 도급 계약서 DOCX 업로드 (비표준계약) | 계약서 자동 구조화 완료 |
| 2. Risk | AI가 리스크 분석 수행 | HIGH 리스크 3건 탐지: 무제한 배상, CR 미정의, 지체상금 0.15%/일 |
| 3. Diff | 이전 버전(v1) 대비 변경 감지 | 페널티 조항 변경 Diff 뷰 시각화 |
| 4. Routing | MZC 기준 자동 라우팅 | 계약팀→법무팀→본부장 + 재무팀 병렬(10억+) |
| 5. Approve | 계약팀이 의견 입력 후 승인 | 다음 단계(법무팀) 자동 진행 |
| 6. Search | "이 고객사와의 과거 CR 조항 처리 이력?" | RAG 검색 결과 표시 |
| 7. Customize | SI 전용 리스크 기준 수정 | 즉시 재분석 반영 |

**발표 핵심 5단계 (시간 제약 시)**: Upload → Risk → Diff → Routing → Search
