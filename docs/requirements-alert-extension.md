# CAS 확장 기능: 영업팀 개인화 Slack 알림 Agent

> Plan A (Contract Agent System) 확장 기능
> 대상: MZC 영업팀 담당자 개인
> 핵심 가치: "DMS 안 열어도, 오늘 뭘 해야 할지 슬랙이 먼저 알려준다"

---

## 1. 문제 정의

### 배경
MZC 영업팀은 하루에도 수십 건의 고객 응대, 계약 관리, 내부 조율을 동시에 처리한다. DMS에 들어가서 내 담당 계약 현황을 파악하는 것 자체가 공수다.

| 상황 | 현재 방식 | 문제 |
|------|-----------|------|
| 오늘 뭐가 급한지 파악 | DMS 직접 접속 + 수동 확인 | 매일 아침 15~20분 낭비 |
| 계약 마감 임박 | 기억 또는 캘린더 수동 등록 | 누락 발생 |
| 고객 이슈 발생 | 이메일/슬랙 분산 | 대응 지연 |
| 미처리 계약 파악 | 담당자 기억 의존 | 장기 방치 계약 발생 |

### 핵심 가설
"매일 아침 9시, 슬랙 DM으로 오늘 내가 해야 할 것이 개인화되어 오면 영업팀은 DMS를 열지 않아도 하루를 시작할 수 있다."

---

## 2. 알림 유형 상세 (4가지)

### ① 오늘의 우선순위 브리핑
- 발송 시점: 매일 09:00 (EventBridge Scheduler)
- 발송 방식: 담당 계약 1건 이상인 영업팀 전원 개인 DM
- AI 판단: 고객사 이력 + 계약 유형 + 지연 기간 종합 (Bedrock KB RAG 활용)

Slack 메시지 포맷:
```
🌅 안녕하세요, {이름}님! 오늘의 계약 브리핑입니다.

🔴 오늘 반드시 처리
- [D-1] A사 NDA 만료 — 오늘까지 갱신 여부 확인 필요
- [미처리 5일] B사 SI 도급 — 계약팀 검토 요청 후 응답 없음

🟡 이번 주 안에 처리
- [D-6] C사 MSA 만료 — 갱신 협의 시작 권장
- [CM검토중 8일] D사 유지보수 — 장기 지연, 상황 확인 필요

🟢 참고
- E사 계약 어제 승인 완료 — 다음 단계(날인) 진행 가능

💡 오늘의 최우선: A사 NDA (D-1)
지난 거래 이력상 A사는 보통 만료 D-3에 갱신 의사를 전달했습니다.
오늘까지 연락 없으면 자동 종료됩니다.
```

### ② 계약 마감일 임박 알림
- 발송 시점: 만료일 기준 D-30 / D-7 / D-3 / D-1 해당일 09:00
- 발송 방식: 해당 계약 담당자 개인 DM

Slack 메시지 포맷:
```
⚠️ 계약 만료 D-{N} 알림
고객사: {고객사명}
계약명: {계약명}
만료일: {만료일} ({N}일 후)
계약금액: {금액}
현재 상태: {상태}

📋 권장 액션
- 갱신 의향 확인 연락 (오늘 중)
- 갱신 시 새 계약서 CAS에 업로드
```

### ③ 미처리 계약 알림
- 발송 시점: 매일 09:00 브리핑에 포함
- 발송 조건:
  - 계약팀 검토 요청 후 3일 이상 응답 없음
  - CM검토중 상태 7일 이상 지속

Slack 메시지 포맷:
```
🔔 미처리 계약 알림
[검토 무응답 — {N}일째]
고객사: {고객사명}
계약: {계약명}
담당 계약팀: {담당자}
→ 계약팀에 직접 확인을 권장합니다.
```

### ④ 고객 이슈 알림 (실시간)
- 발송 시점: CAS 워크플로우에서 반려 또는 이슈 태그 등록 즉시
- 발송 방식: 해당 계약 담당 영업팀 개인 DM

Slack 메시지 포맷:
```
🚨 계약 검토 반려 알림
고객사: {고객사명}
계약: {계약명}
반려 사유: {사유}
반려자: {담당자} ({일시})
→ CAS에서 수정 후 재업로드 필요
AI 권장 수정 문구가 리스크 리포트에 포함되어 있습니다.
```

## 3. 온디맨드 질의

Slack에서 언제든지 직접 질의 가능.

| 질의 예시 | 응답 내용 |
|-----------|-----------|
| `/cas 내 계약 현황` | 담당 계약 전체 목록 + 상태 |
| `/cas A사 계약 어디까지 됐어?` | 해당 고객사 계약 상태 + 다음 액션 |
| `/cas 이번 달 만료 계약` | 이달 만료 계약 목록 |
| `/cas 밀린 거 있어?` | 미처리/지연 계약 전체 요약 |

## 4. 시스템 구성

### 아키텍처

```
[EventBridge Scheduler 09:00]
        ↓
[Alert Agent (Strands SDK)]
  ├─ tool: get_my_contracts(assignee)      ← 담당자별 계약 조회 (코드)
  ├─ tool: get_expiring_contracts(days)    ← 만료 임박 필터 (코드)
  ├─ tool: get_pending_contracts()         ← 미처리/지연 필터 (코드)
  ├─ tool: get_customer_issues()           ← 반려/이슈 조회 (코드)
  └─ tool: generate_priority_briefing()   ← AI 우선순위 판단 + 문구 생성 (LLM + RAG)
        ↓
[Bedrock KB] ← 과거 계약 이력 참조
        ↓
[Slack API] → 개인 DM 발송

--- 온디맨드 ---
[Slack /cas 슬래시 커맨드] → Alert Agent → 즉시 응답
```

### AI vs 코드 역할 분담

| 구성 요소 | 유형 | 근거 |
|-----------|------|------|
| 만료/미처리 계약 조회 | 코드 (tool) | 날짜 계산, 상태 필터 — 확정적 로직 |
| 우선순위 판단 + 문구 생성 | LLM | 맥락 기반 판단, 자연어 생성 |
| 고객사 이력 참조 | RAG (Bedrock KB) | 과거 계약 패턴 검색 |
| Slack 메시지 발송 | 코드 (Slack API) | 확정적 |

## 7. 구현 우선순위 (해커톤 당일)

| 우선순위 | 기능 | 예상 시간 |
|----------|------|-----------|

| 🔴 필수 | 마감 임박 알림 | 30분 |
| 🟡 권장 | 미처리 계약 알림 | 30분 |

> EventBridge 없이 버튼 클릭 수동 트리거로 시연해도 충분.
