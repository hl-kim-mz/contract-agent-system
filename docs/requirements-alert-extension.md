# CAS 확장 기능: 영업팀 개인화 Slack 알림 Agent

> Plan A (Contract Agent System) 확장 기능
> 대상: MZC 영업팀 담당자 개인
> 핵심 가치: "DMS 안 열어도, 오늘 뭘 해야 할지 슬랙이 먼저 알려준다"

## 1. 문제 정의

MZC 영업팀은 하루에도 수십 건의 고객 응대, 계약 관리, 내부 조율을 동시에 처리한다.
DMS에 들어가서 내 담당 계약 현황을 파악하는 것 자체가 공수다.

| 상황 | 현재 방식 | 문제 |
|------|-----------|------|
| 오늘 뭐가 급한지 파악 | DMS 직접 접속 + 수동 확인 | 매일 아침 15~20분 낭비 |
| 계약 마감 임박 | 기억 또는 캘린더 수동 등록 | 누락 발생 |
| 고객 이슈 발생 | 이메일/슬랙 분산, 놓치는 경우 | 대응 지연 |
| 미처리 계약 파악 | 담당자 기억 의존 | 장기 방치 계약 발생 |

핵심 가설:
"매일 아침 9시, 슬랙 DM으로 오늘 내가 해야 할 것이 개인화되어 오면
영업팀은 DMS를 열지 않아도 하루를 시작할 수 있다."

## 2. 알림 유형 4가지

### ① 오늘의 우선순위 브리핑 (매일 09:00, 개인 DM)
발송 조건: 매일 오전 9시 (EventBridge Scheduler)
발송 대상: 담당 계약이 1건 이상인 영업팀 전원 개인 DM

슬랙 메시지 예시:
🌅 안녕하세요, 김영업님! 오늘의 계약 브리핑입니다.

🔴 오늘 반드시 처리
- [D-1] A사 NDA 만료 — 오늘까지 갱신 여부 확인 필요
- [미처리 5일] B사 SI 도급 — 계약팀 검토 요청 후 응답 없음, 직접 연락 필요

🟡 이번 주 안에 처리
- [D-6] C사 MSA 만료 — 이번 주 내 갱신 협의 시작 권장
- [CM검토중 8일] D사 유지보수 — 장기 지연, 상황 확인 필요

🟢 참고
- E사 계약 어제 승인 완료 — 다음 단계(날인) 진행 가능

💡 오늘의 최우선: A사 NDA (D-1)
   지난 거래 이력상 A사는 보통 만료 D-3에 갱신 의사를 전달했습니다.
   오늘까지 연락 없으면 자동 종료됩니다.

AI 판단 로직:
- 단순 날짜 정렬이 아니라 고객사 이력 + 계약 유형 + 지연 기간을 종합해서 우선순위 결정
- 과거 계약 이력 맥락 포함 (Bedrock KB RAG 활용)

### ② 계약 마감일 임박 알림 (D-30/7/3/1, 개인 DM)
발송 조건: 계약 만료일 기준 D-30, D-7, D-3, D-1 해당일 09:00
발송 대상: 해당 계약 담당자 개인 DM

슬랙 메시지 예시:
⚠️ 계약 만료 D-7 알림
고객사: 주식회사 한국물류파트너스
계약명: WMS 구축 SI 도급 계약
만료일: 2026년 5월 16일 (7일 후)
계약금액: 22억원
현재 상태: 날인 완료
권장 액션: 갱신 의향 확인 연락 (오늘 중)

### ③ 미처리 계약 알림
발송 조건:
- 계약팀 검토 요청 후 3일 이상 응답 없음
- CM검토중 상태 7일 이상 지속
매일 09:00 브리핑에 포함

### ④ 고객 이슈 알림 (실시간)
발송 조건: CAS 워크플로우에서 반려 또는 이슈 태그 등록 시
발송 대상: 해당 계약 담당 영업팀 개인 DM

슬랙 메시지 예시:
🚨 계약 검토 반려 알림
고객사: C사
계약: MSA v1
반려 사유: 제7조 손해배상 조항 — 배상한도 미설정, 수정 필요
반려자: 계약팀 최연지
권장 액션: CAS에서 수정 후 재업로드, AI 권장 문구 리스크 리포트에 포함됨

## 3. 온디맨드 질의 (Slack에서 직접)

| 질의 예시 | 응답 |
|-----------|------|
| /cas 내 계약 현황 | 담당 계약 전체 목록 + 상태 |
| /cas A사 계약 어디까지 됐어? | 해당 고객사 계약 상태 + 다음 액션 |
| /cas 이번 달 만료 계약 | 이달 만료 계약 목록 |
| /cas 밀린 거 있어? | 미처리/지연 계약 요약 |

## 4. 시스템 구성

아키텍처:
EventBridge Scheduler 09:00
  → Alert Agent (Strands SDK)
      ├─ tool: get_my_contracts(assignee)
      ├─ tool: get_expiring_contracts(days)
      ├─ tool: get_pending_contracts()
      ├─ tool: get_customer_issues()
      └─ tool: generate_priority_briefing() ← LLM + RAG
  → Slack API → 개인 DM 발송

온디맨드:
Slack /cas 명령어 → Alert Agent → 즉시 응답

AI vs 코드 역할:
- 만료/미처리 계약 조회: 코드 (날짜 계산, 상태 필터)
- 우선순위 판단 + 문구 생성: LLM
- 고객사 이력 참조: RAG (Bedrock KB)
- Slack 메시지 발송: 코드 (Slack API)

## 5. 데이터 모델 추가

cas-contracts 테이블 추가 필드:
- assignee: 담당 영업팀 담당자 이름
- assignee_slack_id: Slack User ID (DM 발송용)
- customer_issues: List (이슈 목록)
- last_contact_at: 고객사 마지막 연락일

cas-slack-users 테이블 (신규):
- employee_id (PK)
- name
- slack_id
- department
- alert_enabled: true/false
- alert_time: "09:00" (개인별 알림 시간)
