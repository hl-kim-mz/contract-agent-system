## 실행 순서 & 의존성 맵

```
시간 ──────────────────────────────────────────────────────────►

[Block A: 즉시 시작 — 병렬]
  ├─ 01. 개발 환경 ─────────────┐
  └─ 02. AWS 계정 & IAM ────────┤
                                │
[Block B: IAM 완료 후 — 병렬]   ▼
  ├─ 03. S3 버킷 ──────────────┐
  ├─ 04. DynamoDB ─────────────┤   ← 3개 병렬 가능
  └─ 05. Bedrock 모델 액세스 ──┤
                                │
[Block C: S3 + 모델 완료 후]    ▼
  ├─ 06. Bedrock KB ───────────┐   ← OpenSearch 15~30분 대기
  └─ 07. Bedrock Guardrails ───┤   ← 콘솔 정책 생성 (인간 필수)
                                │
[Block D: 인프라 완료 후]       ▼
  ├─ 08. MCP Server ───────────┐   ← 병렬 가능
  ├─ 09. 데모 데이터 ──────────┤
  └─ 10. AI Agent 설계 ────────┤
                                │
[Block E: 코드 완료 후]         ▼
  └─ 11. 배포 (EC2 Docker) ────┐
                                │
[Block F: 해커톤 당일]          ▼
  └─ 12. 당일 전환 체크리스트
```

**의존성 요약:**

| 작업 | 선행 조건 | 비고 |
|------|-----------|------|
| 01. 개발 환경 | 없음 | 즉시 시작 |
| 02. AWS IAM | 없음 | 01과 병렬 |
| 03. S3 | 02 완료 | |
| 04. DynamoDB | 02 완료 | 03과 병렬 |
| 05. Bedrock 모델 | 02 완료 | 03, 04와 병렬 |
| 06. Bedrock KB | 03 + 05 완료 | **병목** — OpenSearch 15~30분 |
| 07. Guardrails | 05 완료 | 06과 병렬, **인간 필수** |
| 08. MCP Server | 01 완료 | Node.js 필요 |
| 09. 데모 데이터 | 03 + 04 + 06 완료 | |
| 10. AI Agent | 01 완료 (Groq 테스트) | 09와 병렬 |
| 11. 배포 | 전체 코드 완료 | |
| 12. 당일 체크리스트 | 전체 완료 | D-Day 실행 |

**크리티컬 패스:**
```
02. IAM → 03. S3 → 06. KB (15~30분 대기) → 09. 데모 데이터
```

## 인간 vs AI 역할 분담

### 반드시 인간이 해야 하는 작업

| 작업 | 이유 | 소요 시간 | 가이드 |
|------|------|-----------|--------|
| AWS 계정 생성 & 결제 수단 등록 | 신용카드, 본인인증 | 10분 | [02](02.aws-iam.md) |
| Anthropic FTU 양식 제출 | 비즈니스 판단 | 3분 | [05](05.bedrock-model-access.md) |
| Bedrock Playground 모델 테스트 | 응답 품질 육안 확인 | 2분 | [05](05.bedrock-model-access.md) |
| **Bedrock Guardrails 정책 생성** | 콘솔에서 PII/Prompt Attack 정책 | 5분 | [07](07.bedrock-guardrails.md) |
| Mock 계약서 DOCX 내용 검수 | 도메인 전문성 | 15분 | [09](09.demo-data.md) |
| 프롬프트 품질 판단 & 튜닝 방향 | 리스크 탐지 정확도 판단 | 20분 | [10](10.ai-agent.md) |
| 데모 리허설 & 시나리오 최종 확인 | 발표 흐름 판단 | 15분 | [09](09.demo-data.md) |

**인간 필수 총 공수: 약 1시간 10분** (대기 시간 제외)

### AI에게 위임 가능한 작업

| S3 버킷 생성 | `"ap-northeast-2에 cas-contracts-{팀명} S3 버킷 생성해"` | [03](03.s3-bucket.md) |
| DynamoDB 4개 테이블 + GSI | `"04.dynamodb.md §4-4 CLI 명령 실행해"` | [04](04.dynamodb.md) |

| 작업 | AI 위임 방법 |

## 실행 타임라인 (최적 경로)

2명 기준 (인간 1 + AI 1) 병렬 실행:

```
시간    인간                          AI (Claude Code)
─────┬─────────────────────────────┬────────────────────────────────
 0분 │ AWS 계정 생성 + 결제 등록   │ Python venv + pip install
     │                             │ Node.js 확인
     │                             │
15분 │ IAM 콘솔에서 사용자 생성    │ CLI로 IAM + 정책 자동화
     │ Access Key 복사 → .env      │
     │                             │
20분 │ Anthropic FTU 양식 제출     │ S3 버킷 + DynamoDB 4테이블 (CLI)
     │ Bedrock Playground 테스트   │ MCP compliance.db 초기화
     │                             │
30분 │ Bedrock KB 생성 (콘솔)      │ ← 인간이 콘솔에서 시작
     │ Guardrails 정책 생성 (콘솔) │   (OpenSearch 15~30분 대기)
     │                             │
     │ ┌─ 대기하는 동안 ──────────┐│
     │ │ Mock 계약서 내용 기획    ││ Mock DOCX 4개 자동 생성
     │ │ 데모 시나리오 순서 정리  ││ DOCX 파서 / Rule Engine 코드
     │ │ 프롬프트 방향 설계       ││ difflib Diff 로직 구현
     │ └─────────────────────────┘│
     │                             │
60분 │ KB 생성 완료 확인           │ FastAPI 백엔드 구현 시작
     │ KB ID → .env 기록           │
     │                             │
65분 │ Mock 계약서 내용 검수       │ 데모 데이터 S3 업로드
     │                             │ DynamoDB 시딩 + KB 동기화
     │                             │
75분 │ 프롬프트 품질 검수 & 튜닝   │ Streamlit 프론트엔드 구현
     │                             │ Multi-Agent 코드 구현
     │                             │
90분 │ 데모 리허설                 │ 통합 테스트 + 버그 수정
─────┴─────────────────────────────┴────────────────────────────────
총 약 1.5~2시간 (인프라 + 데이터) + FE/BE 코딩 1~2시간 (AI 위임)
```

## v3 아키텍처 요약

```
┌───────────────────────────────────────────────────────┐
│ Orchestrator Agent (Sonnet) — as_tool() 자율 라우팅     │
│                                                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐    │
│  │ ParsingAgent │  │ RiskAgent    │  │ SearchAgent  │    │
│  │ (Haiku)      │  │ (Sonnet)     │  │ (Haiku)      │    │
│  │ as_tool()    │  │ as_tool()    │  │ as_tool()    │    │
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘    │
│         │                │                │              │
│  ┌──────▼──────────────────────────────────▼──────┐    │
│  │               AWS 인프라                         │    │
│  │  S3 (파일) + DynamoDB (데이터) + KB (RAG 검색)  │    │
│  └─────────────────────────────────────────────────┘    │
│                                                         │
│  ┌─────────────┐  ┌──────────────────────────────┐    │
│  │ MCP Client   │  │ Bedrock Guardrails            │    │
│  │ (compliance) │  │ (PII 마스킹 + 공격 차단)      │    │
│  └─────────────┘  └──────────────────────────────┘    │
│                                                         │
│  Rule Engine (코드 기반) — MZC 라우팅 규칙              │
└─────────────────────────────────────────────────────────┘
```

**설계 원칙**: "AI가 필요한 곳에만 AI를 쓴다."
- **코드**: DOCX 파싱, difflib Diff, Rule Engine 라우팅
- **AI**: 리스크 판단, 자연어 검색, MCP 자율 쿼리, 조항 구조화
