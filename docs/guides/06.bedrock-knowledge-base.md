# 06. Bedrock Knowledge Base 생성

> Phase 5 | 소요 시간: 약 30~45분 (OpenSearch Serverless 프로비저닝 대기 포함)
> 선행 조건: [03. S3 버킷](03.s3-bucket.md), [05. Bedrock 모델 액세스](05.bedrock-model-access.md)
> 참고: [AWS Bedrock Knowledge Base 생성 문서](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-create.html)

> **OpenSearch Serverless 프로비저닝에 약 15~30분 소요. 가능한 먼저 시작할 것.**

---

## 6-1. Knowledge Base 생성

1. Bedrock 콘솔 → 좌측 메뉴 **지식 기반(Knowledge bases)** 클릭
2. **지식 기반** 섹션에서 **생성(Create)** 버튼 클릭 → **벡터 스토어를 사용한 지식 기반** 선택

**Step 1: 지식 기반 세부 정보**

| 필드 | 값 |
|------|-----|
| **지식 기반 이름(Knowledge base name)** | `cas-knowledge-base` |
| **설명(Description)** | CAS 계약서 히스토리 검색용 RAG |
| **IAM 역할** | **새 서비스 역할 생성 및 사용(Create and use a new service role)** 선택 |

3. **태그(Tags)** — 선택사항, 건너뛰기 가능
4. **다음(Next)** 클릭

## 6-2. 데이터 소스 연결 (S3)

> 참고: [S3 데이터 소스 연결 문서](https://docs.aws.amazon.com/bedrock/latest/userguide/s3-data-source-connector.html)

1. 데이터 소스 유형: **Amazon S3** 선택
2. 데이터 소스 이름: `cas-contracts-datasource`

| 필드 | 값 |
|------|-----|
| **S3 버킷** | 현재 계정 선택 → `cas-contracts-{팀명}` 선택 |
| **포함 접두사(Inclusion prefixes)** | (비워둠 — 전체 버킷 대상, 또는 `*.json` 파일만 원하면 나중에 JSON 파일 경로만 업로드) |

3. **콘텐츠 파싱 및 청킹(Content parsing and chunking)** 섹션:
   - **청킹 전략(Chunking strategy)**: **고정 크기 청킹(Fixed-size chunking)** 선택
   - **최대 토큰 수(Max tokens)**: `300` (계약서 조항 단위에 적합)
   - **오버랩 비율(Overlap percentage)**: `10`

> **주의**: 청킹 전략은 데이터 소스 연결 후 변경 불가

## 6-3. 임베딩 모델 선택

**임베딩 모델(Embeddings model)** 섹션:

1. **Amazon** → **Titan Text Embeddings V2** 선택
2. 추가 구성(Additional configurations):
   - **임베딩 유형(Embeddings type)**: float32 (기본값)
   - **벡터 차원(Vector dimensions)**: 1024 (기본값)

## 6-4. 벡터 데이터베이스 선택

**벡터 데이터베이스(Vector database)** 섹션:

1. **새 벡터 스토어 빠른 생성(Quick create a new vector store)** 선택
2. **Amazon OpenSearch Serverless** 선택

> Amazon Bedrock이 자동으로:
> - OpenSearch Serverless 벡터 검색 컬렉션 생성
> - 인덱스 생성 및 필요한 필드 구성
> - 네트워크/데이터 액세스 정책 설정
>
> **이 과정에 약 15~30분 소요된다.**

3. **다음(Next)** 클릭
4. 설정 리뷰 → **생성(Create knowledge base)** 클릭

## 6-5. Knowledge Base ID 메모

1. 생성 완료 후 KB 상세 페이지가 열림
2. **지식 기반 ID(Knowledge base ID)** 값을 복사 (예: `ABCDEFGHIJ`)
3. `.env`에 기록:

```bash
BEDROCK_KB_ID=ABCDEFGHIJ
```

## 6-6. 데이터 소스 동기화 (Sync)

> 참고: [Bedrock KB Sync 문서](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-data-source-sync-ingest.html)

S3에 파일을 업로드한 후, KB에 인덱싱하려면 동기화가 필요하다.

**콘솔에서:**
1. Bedrock 콘솔 → **지식 기반** → `cas-knowledge-base` 클릭
2. **데이터 소스 개요(Data source overview)** 섹션에서 데이터 소스 선택
3. **동기화(Sync)** 버튼 클릭
4. 동기화 상태가 **완료(Complete)**가 될 때까지 대기

**API/코드에서 (애플리케이션에서 자동 동기화할 때):**
```python
import boto3

bedrock_agent = boto3.client('bedrock-agent', region_name='ap-northeast-2')

response = bedrock_agent.start_ingestion_job(
    knowledgeBaseId='ABCDEFGHIJ',
    dataSourceId='데이터소스ID'
)
print(response['ingestionJob']['ingestionJobId'])
```

> 동기화는 증분(incremental) 방식: 추가/수정/삭제된 문서만 처리한다.

## 6-7. KB 검색 테스트

1. Bedrock 콘솔 → **지식 기반** → `cas-knowledge-base` 클릭
2. 우측 **테스트 지식 기반(Test knowledge base)** 패널
3. 모델 선택: **Claude Sonnet 4**
4. 질의 입력: `"A사와의 계약에서 배상 조항은?"` → **실행(Run)**
5. 검색 결과 및 생성된 답변 확인

> **Plan B**: KB 생성 실패 시 BM25 + AI 요약으로 대체. 코드에서 `search_history` 도구를 BM25 구현으로 교체.
