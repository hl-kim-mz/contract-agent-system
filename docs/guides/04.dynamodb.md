# 04. DynamoDB 테이블 생성

> Phase 3 | 소요 시간: 약 10분 | 선행 조건: [02. AWS IAM](02.aws-iam.md)
> 참고: [AWS DynamoDB Getting Started](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/getting-started-step-1.html)

---

## 테이블 설계 요약

4개 테이블을 생성한다. 모두 **On-Demand** 용량 모드를 사용한다.

| 테이블명 | PK | GSI | 용도 |
|----------|-----|-----|------|
| `cas-contracts` | `id` (String) | — | 계약서 메타데이터 + 파싱 결과 |
| `cas-risk-reports` | `id` (String) | `contract_id-index` (PK: `contract_id`) | 리스크 리포트 |
| `cas-workflow-steps` | `id` (String) | `contract_id-index` (PK: `contract_id`) | 워크플로우 검토 단계 |
| `cas-prompt-templates` | `id` (String) | `contract_type-index` (PK: `contract_type`) | 프롬프트 템플릿 |

---

## 4-1. 테이블 생성 (콘솔 — 4회 반복)

아래 절차를 각 테이블마다 반복한다.

1. AWS 콘솔 → 상단 검색바에 `DynamoDB` 입력 → **DynamoDB** 서비스 클릭
2. 리전 확인: **아시아 태평양 (서울) ap-northeast-2**
3. 좌측 메뉴 **테이블(Tables)** 클릭
4. **테이블 생성(Create table)** 버튼 클릭

**테이블 세부 정보(Table details):**

| 필드 | 값 (첫 번째 테이블 예시) |
|------|--------------------------|
| **테이블 이름(Table name)** | `cas-contracts` |
| **파티션 키(Partition key)** | `id` → 드롭다운에서 **문자열(String)** 선택 |
| **정렬 키(Sort key)** | (비워둠 — 사용하지 않음) |

5. **테이블 설정(Table settings)** → **설정 사용자 지정(Customize settings)** 선택

> **중요**: "기본 설정(Default settings)"을 선택하면 프로비저닝 모드가 기본값으로 설정된다. 반드시 **설정 사용자 지정**을 선택해야 On-Demand 모드를 지정할 수 있다.

6. **읽기/쓰기 용량 설정(Read/write capacity settings)**:
   - **용량 모드(Capacity mode)**: **온디맨드(On-demand)** 선택

7. **테이블 생성(Create table)** 클릭
8. 상태가 **활성(Active)**으로 바뀔 때까지 대기 (보통 수 초)

## 4-2. GSI 추가 (해당 테이블만)

`cas-risk-reports`, `cas-workflow-steps`, `cas-prompt-templates` 3개 테이블에 GSI를 추가한다.

### 방법 A: 테이블 생성 시 함께 설정

테이블 생성 페이지의 **설정 사용자 지정** 선택 후, 아래로 스크롤하면 **보조 인덱스(Secondary indexes)** 섹션이 있다.

1. **글로벌 인덱스 생성(Create global index)** 버튼 클릭
2. 아래 값을 입력:

**cas-risk-reports GSI:**

| 필드 | 값 |
|------|-----|
| **파티션 키(Partition key)** | `contract_id` (String) |
| **정렬 키(Sort key)** | (비워둠) |
| **인덱스 이름(Index name)** | `contract_id-index` |
| **속성 프로젝션(Attribute projections)** | **모두(All)** 선택 |

3. **인덱스 생성(Create index)** 클릭

**cas-workflow-steps GSI:**

| 필드 | 값 |
|------|-----|
| **파티션 키(Partition key)** | `contract_id` (String) |
| **인덱스 이름(Index name)** | `contract_id-index` |
| **속성 프로젝션** | **모두(All)** |

**cas-prompt-templates GSI:**

| 필드 | 값 |
|------|-----|
| **파티션 키(Partition key)** | `contract_type` (String) |
| **인덱스 이름(Index name)** | `contract_type-index` |
| **속성 프로젝션** | **모두(All)** |

### 방법 B: 테이블 생성 후 추가

1. DynamoDB 콘솔 → **테이블(Tables)** → 테이블 이름 클릭
2. **인덱스(Indexes)** 탭 클릭
3. **인덱스 생성(Create index)** 버튼 클릭
4. 위와 동일한 값 입력 → **인덱스 생성(Create index)** 클릭
5. 상태가 **활성(Active)**이 될 때까지 대기

## 4-3. AWS CLI로 일괄 생성 (대안)

콘솔 반복이 번거롭다면 CLI로 한 번에 생성할 수 있다:

```bash
# 테이블 1: cas-contracts (GSI 없음)
aws dynamodb create-table \
  --table-name cas-contracts \
  --attribute-definitions AttributeName=id,AttributeType=S \
  --key-schema AttributeName=id,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST \
  --region ap-northeast-2

# 테이블 2: cas-risk-reports (GSI: contract_id)
aws dynamodb create-table \
  --table-name cas-risk-reports \
  --attribute-definitions \
    AttributeName=id,AttributeType=S \
    AttributeName=contract_id,AttributeType=S \
  --key-schema AttributeName=id,KeyType=HASH \
  --global-secondary-indexes \
    '[{
      "IndexName": "contract_id-index",
      "KeySchema": [{"AttributeName":"contract_id","KeyType":"HASH"}],
      "Projection": {"ProjectionType":"ALL"}
    }]' \
  --billing-mode PAY_PER_REQUEST \
  --region ap-northeast-2

# 테이블 3: cas-workflow-steps (GSI: contract_id)
aws dynamodb create-table \
  --table-name cas-workflow-steps \
  --attribute-definitions \
    AttributeName=id,AttributeType=S \
    AttributeName=contract_id,AttributeType=S \
  --key-schema AttributeName=id,KeyType=HASH \
  --global-secondary-indexes \
    '[{
      "IndexName": "contract_id-index",
      "KeySchema": [{"AttributeName":"contract_id","KeyType":"HASH"}],
      "Projection": {"ProjectionType":"ALL"}
    }]' \
  --billing-mode PAY_PER_REQUEST \
  --region ap-northeast-2

# 테이블 4: cas-prompt-templates (GSI: contract_type)
aws dynamodb create-table \
  --table-name cas-prompt-templates \
  --attribute-definitions \
    AttributeName=id,AttributeType=S \
    AttributeName=contract_type,AttributeType=S \
  --key-schema AttributeName=id,KeyType=HASH \
  --global-secondary-indexes \
    '[{
      "IndexName": "contract_type-index",
      "KeySchema": [{"AttributeName":"contract_type","KeyType":"HASH"}],
      "Projection": {"ProjectionType":"ALL"}
    }]' \
  --billing-mode PAY_PER_REQUEST \
  --region ap-northeast-2
```

## 4-4. 테이블 생성 확인

```bash
aws dynamodb list-tables --region ap-northeast-2
# 또는 콘솔: DynamoDB → 테이블(Tables) 에서 4개 테이블 모두 "활성(Active)" 확인
```

## 4-5. 데이터 모델 상세 (DynamoDB 아이템 구조)

DynamoDB는 스키마리스이므로 테이블 생성 시 PK/SK만 정의하면 된다.
실제 아이템의 속성은 코드에서 넣을 때 자유롭게 추가한다.

**cas-contracts 아이템 예시:**
```json
{
  "id": "contract-uuid-001",
  "customer_name": "A고객사",
  "contract_type": "SI",
  "version": 1,
  "status": "RISK_REVIEWED",
  "is_standard": false,
  "s3_key": "A고객사/contract-uuid-001/v1.docx",
  "uploaded_at": "2026-05-10T09:00:00Z",
  "uploaded_by": "영업팀 홍길동",
  "clauses": [
    {
      "id": "clause_001",
      "type": "liability",
      "title": "제10조 (손해배상)",
      "content": "원문 텍스트...",
      "paragraph": 10
    }
  ],
  "diff_report": null
}
```

**cas-risk-reports 아이템 예시:**
