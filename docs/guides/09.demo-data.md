## 9-1. Mock 계약서 DOCX 작성

데모를 위해 최소 4개의 Mock 계약서 DOCX를 준비한다.

| 파일명 | 유형 | 목적 |
|--------|------|------|
| `A사_SI도급_v1.docx` | SI 도급 (비표준) | 리스크 탐지 데모 — HIGH 3건 |
| `A사_SI도급_v2.docx` | SI 도급 (비표준, 수정) | Diff 데모 — v1 대비 변경 |
| `B사_NDA_v1.docx` | NDA (표준) | LOW 리스크 — 자체 승인 데모 |
| `C사_MSA_v1.docx` | MSA (비표준) | 검색(RAG) 히스토리 데모 |

**SI 도급 v1에 반드시 포함할 리스크 조항:**
- 손해배상: 배상한도 미설정 → HIGH (무제한 배상책임)
- CR 절차: 변경요청 처리 기준 없음 → HIGH (CR 절차 미정의)
- 지체상금: 0.15%/일 → MEDIUM (MZC 기준 0.05% 초과)
- 계약금액: 15억원 → 재무팀 병렬 검토 트리거

**v2에서 변경할 포인트 (Diff 시나리오):**
- 지체상금율: 0.15% → 0.08% (개선, 여전히 초과)
- 배상한도 추가: "계약금액의 200% 이내" (여전히 MZC 기준 100% 초과)

## 9-4. RAG 검색용 KB 동기화

파싱 JSON을 S3에 업로드하고 Bedrock KB를 동기화한다.

```bash
# 1. 파싱 JSON 업로드 (KB 인덱싱 대상)
aws s3 cp samples/A사_SI도급_v1.json s3://cas-contracts-{팀명}/A사/contract-001/v1.json
aws s3 cp samples/B사_NDA_v1.json   s3://cas-contracts-{팀명}/B사/contract-002/v1.json
aws s3 cp samples/C사_MSA_v1.json   s3://cas-contracts-{팀명}/C사/contract-003/v1.json

# 2. KB 동기화 트리거
aws bedrock-agent start-ingestion-job \
  --knowledge-base-id {KB_ID} \
  --data-source-id {DATA_SOURCE_ID} \
  --region us-west-2
```

## 9-5. 데모 시나리오 리허설 체크리스트

| # | 시나리오 단계 | 검증 항목 | 통과 |
|---|--------------|-----------|------|
| 1 | DOCX 업로드 | Streamlit에서 드래그&드롭 → S3 저장 확인 | ☐ |
| 2 | AI 리스크 분석 | RiskAgent → HIGH 3건 탐지 (배상, CR, 지체상금) | ☐ |
| 3 | 리스크 리포트 | 색상 코딩 뱃지 (HIGH: red, MEDIUM: orange, LOW: green) | ☐ |
| 4 | Diff 뷰 | v1→v2 조항 변경사항 + 리스크 영향 요약 | ☐ |
| 5 | 워크플로우 라우팅 | Rule Engine → 계약팀→법무팀→본부장 + 재무팀 병렬 | ☐ |
| 6 | 승인/반려 Mock | 검토자 의견 입력 + 승인 → 다음 단계 전이 | ☐ |
| 7 | MCP 규정 조회 | "사내 규정 확인해줘" → mcp-server-sqlite 자율 쿼리 | ☐ |
| 8 | RAG 검색 | "과거 CR 조항 이력?" → Bedrock KB 시맨틱 검색 | ☐ |
| 9 | Guardrails | 악성 프롬프트 → 즉시 차단 | ☐ |
