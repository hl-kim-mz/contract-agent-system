## 8-1. Strands SDK Agent 구성

```python
# agents/config.py
import os
from strands import Agent
from strands.models import BedrockModel
from strands.models.litellm import LiteLLMModel

def get_model():
    """MODEL_PROVIDER 환경변수에 따라 모델 전환"""
    provider = os.getenv("MODEL_PROVIDER", "groq")

    if provider == "bedrock":
        return BedrockModel(
            model_id="anthropic.claude-3-5-sonnet-20241022-v2:0",
            region_name="ap-northeast-2",
            temperature=0.3,
            streaming=True
        )

    # 사전 개발용 Groq (LiteLLM 경유)
    return LiteLLMModel(
        client_args={"api_key": os.getenv("GROQ_API_KEY")},
        model_id="groq/llama-3.3-70b-versatile",
        params={"max_tokens": 4096, "temperature": 0.3}
    )
```

## 8-3. Agent 초기화

```python
# agents/legal_agent.py
from strands import Agent
from agents.config import get_model
from tools.legal_tools import check_risk, diff_with_previous, analyze_financials

model = get_model()

legal_agent = Agent(
    model=model,
    system_prompt="당신은 메가존클라우드의 계약 리스크 분석 전문가입니다.",
    tools=[check_risk, diff_with_previous, analyze_financials]
)
```

## 8-4. 프롬프트 튜닝 가이드

프롬프트 품질은 리스크 탐지 정확도에 직결된다. Mock 계약서로 반복 테스트하며 튜닝한다.

**튜닝 체크리스트:**

| # | 검증 항목 | 기대 결과 |
|---|----------|-----------|
| 1 | SI 계약 리스크 탐지 | 9개 유형 중 해당 조항 모두 탐지 |
| 2 | risk_level 정확도 | MZC 기준표와 일치 |
| 3 | recommendation 품질 | 실무에서 바로 활용 가능한 수준 |
| 4 | financial_impact | 정성적이지만 구체적인 영향 설명 |
| 5 | JSON 출력 포맷 | Risk Report JSON 스키마 준수 |
| 6 | 한국어 품질 | 법률 용어 자연스러운 한국어 |

**프롬프트 수정 → 재테스트 루프:**
1. Mock 계약서로 Legal Agent 실행
2. 출력 리포트 검토
3. 누락/오탐지 조항 식별
4. 시스템 프롬프트 수정 (DynamoDB `cas-prompt-templates`)
5. 1~4 반복
