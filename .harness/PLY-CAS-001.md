## 3. 워크플로우 라우팅 규칙

| 조건 | 라우팅 대상 | 필수 승인 단계 |
|------|------------|---------------|
| Overall: HIGH | 법무팀 → 팀장 → 본부장 | 3단계 |
| Overall: MEDIUM | 팀장 → 담당 임원 | 2단계 |
| Overall: LOW | 담당자 자체 승인 | 1단계 |
| 계약금액 10억 이상 | 재무팀 병렬 검토 추가 | +1 병렬 |
| IP 이전 조항 포함 | 기술법무 검토 추가 | +1 병렬 |

## 4. 동일 고객사 판별 기준

- `customer_name` 소문자 변환 + 앞뒤 공백 제거 후 문자열 일치로 판별
- 예: `"메가존클라우드 "` = `"메가존클라우드"` (동일 처리)
- 동일 고객사 + 동일 `contract_type` 조합의 계약서가 이미 존재하면 Diff Agent 실행 대상
- 이전 버전 없으면 Diff 생략, 신규 계약서로 처리

---

## 5. 중복 업로드 처리 규칙

- 동일 고객사(`customer_name`) + 동일 `contract_type`의 계약서 재업로드 시:
  - 기존 계약서는 유지 (삭제 없음)
  - 신규 업로드는 `version` 자동 증가 (예: v1 → v2)
  - Diff Agent가 이전 버전 자동 참조

---

## 6. 오류 처리 정책

| 단계 | 오류 유형 | 처리 방식 |
|------|-----------|-----------|
| 파일 업로드 | 지원 형식 아님 (DOCX 외) | 400 에러 반환, 업로드 차단 |
| 파일 업로드 | 10MB 초과 | 400 에러 반환, 업로드 차단 |
| Parsing Agent | 텍스트 추출 실패 | `status = ERROR`, 사용자에게 오류 메시지 표시 |
| Legal Review Agent | Bedrock API 타임아웃 | `status = ERROR`, 재시도 안내 메시지 표시 |
| Workflow Agent | 라우팅 실패 | `status = ERROR`, 수동 지정 안내 |
| 공통 | Agent 예외 발생 | 해당 계약서 `status = ERROR` 기록, 다른 계약서 영향 없음 |

- MVP 기준 자동 재시도 없음 — 사용자가 수동으로 재분석 요청
